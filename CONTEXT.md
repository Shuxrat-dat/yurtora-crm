# Yurtora CRM

Yurtora CRM — CRM для учебных центров (продукт Yurtora); исходно для одного центра (один филиал, ~500 учеников, рост до ~1000).
Направления: английский, русский, математика, физика, химия, биология.
Ученики: дети, подростки, взрослые (у детей есть родители/контакты).
Проект заменяет Soff CRM. Бюджет маленький, поэтому всё должно быть простым.

## Стек
- Python 3.12, Django 5.x, PostgreSQL 16
- Шаблоны Django + HTMX + Tailwind (без отдельного SPA-фронта)
- Docker + docker-compose, настройки только через переменные окружения
- Тесты: pytest + pytest-django. Линтер/форматтер: ruff

## Правила работы
1. Сначала план, потом код. Не меняй файлы, пока я не подтвердил план.
2. Меняй только то, что относится к задаче. Не рефакторь чужой код.
3. Не добавляй зависимости и абстракции без причины. Объясняй каждую новую зависимость.
4. Секреты, пароли и ключи не пишем в код. Только `.env` (в .gitignore) и `.env.example`.
5. К каждой фичи пиши тесты. Не говори «готово», пока не запустил тесты, ruff и `manage.py check`, и не показал результат.
6. Если команда или тест падает, найди причину и исправь её. Не скрывай и не отключай проверки.
7. Миграции создаются через `makemigrations`, вручную не правим.

## Договорённости по данным
- Деньги хранятся целым числом в сумах (BigIntegerField), без float.
- Баланс ученика НЕ хранится полем. Каждая оплата, скидка, возврат — отдельная
  запись, которую не редактируют и не удаляют (ошибка исправляется корректирующей
  записью). Баланс считается из записей.
- Свой User-model создаётся с самого начала (AUTH_USER_MODEL).
- Часовой пояс: Asia/Tashkent.

## Роли (MVP)
director, administrator, teacher. Права проверяются на сервере, а не скрытием кнопок.

## Структура
